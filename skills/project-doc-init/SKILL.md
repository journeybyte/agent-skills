# Project Doc Initializer

## Description

自动分析项目，生成包含行为准则、AI工作原则、场景化导航的 CLAUDE.md 及配套子文档。无需额外参数，直接激活即可。

## Instructions

1. 读取项目配置文件（package.json / pyproject.toml / go.mod 等）和目录结构，识别技术栈与架构特点
2. 按 Prompt Template 生成文档：CLAUDE.md（含行为准则、工作原则、场景导航）+ docs/ 子文档
3. 输出文件结构、完整文档内容和使用说明

---

| 文件 | 说明 |
|------|------|
| CLAUDE.md | 主索引（含行为准则+工作原则+场景导航） |
| docs/PROJECT.md | 技术栈、目录结构 |
| docs/CODE_STYLE.md | 编码规范 |
| docs/COMPONENT.md | 组件开发规范 |

场景导航表示例：

| 任务类型 | 文档路径 | 核心内容 |
|---------|---------|---------|
| 了解项目 | docs/PROJECT.md | 技术栈、目录结构 |
| 编写代码 | docs/CODE_STYLE.md | 编码规范 |
| 开发组件 | docs/COMPONENT.md | 组件规范、Props定义 |
| 调试排错 | docs/DEBUG.md | 常见问题、调试方法 |

## Prompt Template

当创建具体项目的文档时，使用以下提示词模板：

````
你是项目文档规划专家。请为当前项目设计一套 AI 友好的文档体系。

## 项目信息
【从项目文件中自动分析获取】

## 任务要求

请按以下步骤设计：

### Step 1: 分析项目特点
识别技术栈、架构模式、项目结构、开发规范和常用场景。

### Step 2: 设计文档结构
设计原则：
1. CLAUDE.md（主索引）: 行为准则 + AI工作原则 + 技术栈概览 + 场景导航 + 常用命令
2. docs/ 目录: 按功能模块拆分的详细文档

### Step 3: 设计场景化导航表
根据项目实际设计导航表：

| 任务类型 | 文档路径 | 核心内容 |
|---------|---------|---------|
| 了解项目 | docs/PROJECT.md | 技术栈、目录结构 |
| 编写代码 | docs/CODE_STYLE.md | 编码规范 |
| ... | ... | ... |

### Step 4: 定义行为准则与工作原则

**行为准则**（必须原样嵌入 CLAUDE.md，不可省略、不可改写）：

```markdown
## 行为准则

**准则偏向谨慎，简单任务灵活判断。**

### 1. Think Before Coding
**不假设、不隐藏困惑、展示权衡。**
- 不确定时先问，不要猜测
- 存在多种理解时，列出所有可能
- 有更简单的方案就提出来
- 搞不明白就停下来，说清楚哪里不明白

### 2. Simplicity First
**最小代码解决问题，不做推测性设计。**
- 不做需求范围外的功能
- 单次使用的代码不做抽象
- 没要求的"灵活性"和"可配置性"不加
- 不为不可能的场景写错误处理
- 200行能写成50行就重写

### 3. Surgical Changes
**只改必须改的，清理自己制造的混乱。**
- 不"顺手优化"周边无关代码
- 不重构没坏的东西
- 遵循现有风格，即使你不认同
- 发现无关死代码提出来，不删

### 4. Goal-Driven Execution
**定义成功标准，循环验证。**
- "加验证" → "写无效输入测试，然后让它通过"
- "修bug" → "写复现测试，然后让它通过"
- "重构X" → "确保重构前后测试都通过"
- 多步任务列出计划：1. [步骤] → verify: [检查]
````

**AI 工作原则**（必须嵌入 CLAUDE.md，不可省略）：

```markdown
## AI 工作原则

1. **开发前必读** — 编码前先读项目文档，了解结构、规范和约束
2. **按图索骥** — 按场景导航表定位文档，不凭经验猜测
3. **不懂再查** — 先按文档执行，未覆盖时再搜索代码/查阅资料
```

### Step 5: 编写文档内容

- CLAUDE.md: 行为准则与工作原则（按 Step 4 原文） + 技术栈概览 + 场景导航表 + 常用命令 + 精简注意事项
- 各子文档: 规范要点 + 注意事项

## 输出要求

1. 提供完整的文件列表
2. 编写每个文档的核心内容
3. 确保文档之间有交叉引用
4. 文档命名符合项目实际
5. 不限制技术栈，基于项目实际生成

## 格式要求

- CLAUDE.md 控制在 80-120 行（小项目偏下限，大项目偏上限）
- 子文档单文件不超过 200 行
- 使用 Markdown 表格做导航
- 注意事项精简为要点列表，不展开说明
- **禁止套话**：不要"本文档将介绍..."等开头，直接写内容
- **只写必要信息**：规范、约束、关键路径，不写显而易见的内容
- 代码示例仅限必要场景，优先用描述说明规范

