# 反馈格式

所有异常、降级与交付反馈统一按本文件输出，避免不同运行之间措辞漂移。

## 问题清单

信息不足、无法识别、无法确认时使用统一附表：

| 缺失项 | 原因 | 需要补充 |
|---|---|---|
| [具体字段或事实] | [为什么无法从项目确认] | [用户需提供的具体信息] |

- 无问题可列时省略整表，不输出空表。
- 问题清单只在交付说明中输出一次，不在文档正文里写"待确认"。

## 交付摘要

初始化/更新模式必须输出全部 6 个编号项；单产物模式只输出第 2、6 项。已有文件被整体重写时标 `[重写]`，不标 `[新增]`。

```
1. 模式与档位：[初始化/更新/单产物]；[L1/L2/L3]；触发依据：[可确认信号]；未生成升级项：[无 / 列出]
2. 文件状态：
   - [文件名] [状态前缀] — [一句说明]   ← 每个文件一个子项
   - ...
3. 变更依据：[变更差异清单引用 / 无]   ← 更新模式列出差异条目；初始化写"无"
4. 重写说明：[无 / 文件名 + 重写原因]   ← 整体重写（用户显式要求从零重建，或现有文档与实际严重不符）时填写
5. 降级与后续：[无 / 降级项 + 原因；建议后续补充项]   ← 含 [降级] 与未覆盖领域
6. 问题清单：[见附表 / 无]
```

- "6 项"指 6 个编号项，不是 6 个物理行；第 2 项允许多行子列表，其余项各占一行。
- 每个编号项必须出现，值为"无"时写"无"，不省略项；单产物模式只输出第 2、6 项。
- 第 2 项的子列表按状态前缀分组，顺序为 `[新增]` → `[修订]` → `[重写]` → `[未动]` → `[已删除]`；同组内按文件相对路径排序，不强制特定大小写顺序。
- `[降级]` 是注记，不是独立分组；追加在状态前缀后（如 `[修订][降级]`），不参与分组排序。
- 删除/重命名的原因写进第 2 项该文件说明；降级原因同时写进第 5 项。

## 状态前缀

| 前缀 | 含义 |
|---|---|
| `[未动]` | 已存在且本次无需改动 |
| `[修订]` | 仅受影响章节更新 |
| `[新增]` | 本次新建 |
| `[已删除]` | 本次移除，附原因 |
| `[重写]` | 已有文件本次整体重新生成（用户显式要求从零重建，或更新模式下与实际严重不符），附原因 |
| `[降级]` | 注记：按"常见问题与处理"简化处理，附降级原因；追加在状态前缀后 |
